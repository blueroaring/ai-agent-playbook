# 13 · 文件编辑的前置条件 —— "file has not been read" 反复发生怎么根治

> **适用范围**：症状 `[通病]`（任何"读前置/版本 CAS"的编辑工具都会这样），
> 具体包名、错误码、事件名 `[本机]`（属 DSH = DeepSeek Harness）。
> **谁该读**：所有用工具改文件的 Agent —— 尤其是**跨会话/跨工作区连续改代码**的那种。
> **一句话**：你的工具链要求"**先读后写**"，而你以为"**文件在盘上、我记得它长什么样**"就够了。
> 两者不一致时，报错只是形式问题，**真正危险的是没有报错的那些情况**（见第 6 节）。

---

## 1. 症状

改文件时反复撞到下面这句，同一个文件下一次还是撞：

```
Error: cannot modify "<path>": file has not been read — read the file, then retry
```

变体（不同时机）：

```
cannot edit "<path>": file changed since it was read — re-read the file, then retry
```

```
cannot modify "<path>": file has not been read — read the file, then retry
[exit code: ...]                ← 与"沙箱拒绝"长得像，但成因完全不同，见第 5 节
```

**诊断特征**：报错**指向具体文件**、**不涉及权限**、**重新读一次再改就好**。
如果你正在"因为报错而重读"，那你已经在支付这笔税了 —— 本篇是把这笔税省掉。

---

## 2. 根因：编辑是"基于一次已确认的观察"的 CAS，不是"基于盘上的文件" `[本机]`

DSH 里这套行为由 `dsh-fs-observation-policy` 强制。三条机制，记住就够：

1. **观察按会话记账**。每次成功操作后，工具发一个 `fs/observed` 事件，策略插件把它记到
   **当前 agent 会话**（弱引用持有）→ `targetKey → {present, version} | {absent}`。
   换会话、换 Agent、换了宿主进程 → **这张表是空的**。

2. **`edit` 必须命中一条 `present` 观察**，否则直接拒绝，错误码 `FS_NOT_OBSERVED`：
   - 没有任何观察 → `FS_NOT_OBSERVED`（就是本句报错）
   - 观察到的是"**文件不存在**" → `FS_NOT_FOUND`
   - 有观察但**版本变了**（别人改过） → `FS_STALE_VERSION`

3. **`write` 不是后门**：未观察的文件上，`write` 用的是 `createIfAbsent` 守卫，
   文件已存在时**同样拒绝**并给出同一句话。
   → **没有"绕过读直接覆盖"的合法路径**，别把 `write` 当逃生舱。

> 类比：这不是编辑器在耍脾气，而是 **乐观并发控制（CAS）**。
> 报错的意思是"我没有一个可信的基线版本，凭什么允许你改？"
> 你唯一能提供基线的方式，就是**真的读一次**。

---

## 3. 实测证据矩阵 `[本机]`（2026-09-17，本机一次性跑完）

| # | 前置动作 | 调用的工具 | 结果 |
|---|---|---|---|
| 1 | 用 shell 创建文件（**未经 read**） | `edit` | ❌ `FS_NOT_OBSERVED`（本篇那句话） |
| 2 | 同上 | `write`（想全量覆盖） | ❌ **同样报未读** → 覆盖不是逃生舱 |
| 3 | `read` **只读 2 行**（文件共 21 行） | `edit` **第 21 行** | ✅ 成功 |
| 4 | 观察建立后，用 shell 往文件**追加内容** | `edit` | ❌ `file changed since it was read` |
| 5 | 重新 `read` 之后 | `edit` | ✅ 成功 |

**读出来的两条反直觉结论**：

- **观察的粒度是"文件版本"，不是"行窗口"**。`read` 带 `limit`/`offset` **也建立完整观察** ——
  大文件不必整读，读一个窗口就够（但这只解决"能不能改"，**不解决"改得对不对"**，见第 6 节）。
- **版本会因任何外部写入而失效**。哪怕是 `Add-Content` 追加一行、或另一个 Agent 改了一个字符 ——
  你手上那条观察就过期了。**你改文件的同时别人也在改** = 每次改前都要重读。

---

## 4. 解法：把"读"当成编辑语法的一部分，而不是一次性的准备工作

### 5 条硬规则（按成本从低到高）

1. **改哪个文件，就在本次会话里先 `read` 它。** 不靠记忆、不靠"我刚才在别处看过"。
2. **`read` 与 `edit` 紧挨着下**（同一回合内成对出现）。中间别插入可能改文件的外部命令。
3. **`write` 对已存在文件同样需要先读** → 别把它当兜底；它和 `edit` 一样要观察。
4. **只对新建文件用 `write`**（新建 → 观察记的是 absent，随后也无需再读）。
5. **用外部命令（shell / 脚本 / 另一个 Agent）改过文件后，视为观察作废**，下次编辑前重读。

### 三个最容易踩的触发场景（占绝大多数复发）

| 场景 | 为什么观察是空的 | 正确动作 |
|---|---|---|
| 文件是**上一个会话**建的/改的，用户现在让你改 | 观察表按会话隔离 | 直接 `read` 再 `edit` |
| 你只用 `grep` / `glob` / shell `Get-Content` 看过内容 | **它们不建立观察** | 补一次 `read` |
| 你正要改**另一个工作区/另一个项目**的文件 | 常是跨会话上下文，且可能被别的进程改 | `read` 后再 `edit` |
| 你刚跑完一个脚本/工具改了该文件 | 版本已变 | 重读 |

> 只要能**读**，就一定能改。`read` 报"文件不存在"时别慌：那本身是一次有效观察（记为 absent），
> 此时 `write` 可以安全地**创建**它；但若文件后来被别人创建，`write` 会拒绝而不是覆盖 —— 这是保护，不是故障。

### 给系统提示词的写法（可复制）

```
改任何已存在的文件前，先调用 read 建立观察；read 与 edit 在同一回合内成对出现。
不要用 shell/grep 的读取替代 read。外部工具改过文件后必须重读。
```

## 5. 与"沙箱拒绝"的区别（别修错地方）`[通病]`

两种报错都发生在"想写但写不了"，但成因和处置完全不同：

| 现象 | 归因 | 处置 |
|---|---|---|
| `cannot modify ...: file has not been read — read the file, then retry` | **前置条件**未满足 | 读一次，重试 |
| `cannot edit ...: file changed since it was read — re-read the file, then retry` | **版本过期** | 重读，重试（内容一定是别人改过） |
| `[sandbox: file access denied under <mode> mode]` | **策略/权限** | 需要一次更宽权限的授权重试，**读多少次都没用** |

**判据**：报错里出现 `read`/`re-read` → 是前置条件；出现 `sandbox`/`denied` → 是权限。
把权限问题当"多读几次"处理，会白白耗尽重试预算。

## 6. 真正的风险不是报错，而是"没报错的那一半" `[通病]`

这一节比上面所有内容都重要。

**报错 = 工具在保护你**。它拦住的是"基于旧内容的盲改"。反过来，以下几种情况工具**不会报错**，
但后果一样或更糟：

1. **只读了窗口就改全文** ← 本篇第 3 节证明了这**能过**。
   工具只校验版本，不校验"你看过那段"。你基于第 1–2 行的心智模型去改第 21 行，
   **它照改不误**。→ 结论：**"只读 2 行就改"是合法的，但通常是不负责任的。**
   改哪段就读哪段，或对关键文件整读。
2. **依赖记忆里的文件内容**。上一次会话记住的内容 + 这一次读到的版本号 = 一个自洽的谎言。
3. **"没有 `FS_STALE_VERSION`"不等于"我刚读过"**。这两个是不同的失败模式：
   前者保证基线新鲜，后者保证你真的看过。

**推论（可迁移）**：任何"读前置 + 版本 CAS"的工具集，都只保证**并发安全**，
不保证**语义正确**。前者靠工具，后者只能靠你**真的读了那段**。

## 7. 验证（在你自己的机器上复现这 5 行）

用一个临时文件，5 步走完，能一次性把机制钉死：

```powershell
# ① 用 shell 创建 → 不建立观察
$p = "<workspace>\.tmp-obs-test.md"
1..20 | ForEach-Object { "line $_" } | Set-Content -Path $p -Encoding utf8
Add-Content -Path $p -Value "MARKER_TAIL" -Encoding utf8
```

```
② 直接 edit（改第 1 行）        → 期望 FS_NOT_OBSERVED
③ 直接用 write 覆盖             → 期望同样报"未读"（证明没有后门）
④ read limit=2（只读 2 行）
⑤ edit 改第 21 行               → 期望成功（证明观察是文件级，不是行窗口）
⑥ shell 追加一行 → 再 edit       → 期望 "file changed since it was read"
⑦ read 一次 → 再 edit            → 期望成功
```

**判定标准**：②③ 必须失败、⑤ 必须成功 —— 如果 ⑤ 在你那里失败（要求整读），
说明你的部署把观察做成了行级/整读级，**那第 3 节的省时技巧就不要用**，其余结论不变。
⑦ 之后**删掉临时文件**。
